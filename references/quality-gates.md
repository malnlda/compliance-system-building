# 交付前质量检查

## 一、所有成果

1. 基准一致：成果中的机构、职务、部门、领域、等级、制度名称与体系设计基准一致；依赖“建议”状态事项的，已标注征求意见稿并在交付说明中列出。
2. 前序一致：与已完成成果（特别是职责清单、合规管理办法、风险库）无矛盾；发现前序成果问题的已在对话中报告，未擅自回改。
3. 诊断支撑：主要设计安排能对应到诊断发现、风险库或规范要求。
4. 依据核验：客户文件引用的规范均已核验并记录；适用和参照区分正确。
5. 委托范围：未超出合同约定的数量和范围；超范围建议已在对话中提出。
6. 无编造：所有事实和数据有材料来源；缺失内容已用占位符标示并在交付说明中列出。
7. 文体正确：符合 [writing-style.md](writing-style.md) 对应文体的规则。
8. 范本残留：按本文件第三节执行扫描，结果逐项处理。
9. 中文检查：扫描拉丁字符，每处均属允许的例外。
10. 单一文件：只更新了目标成果文件和工作底稿中的成果对照、核验记录等必要部分，没有生成副本或流程文件。

## 二、按成果类型的附加检查

诊断章节：证据分层已标明，未以“未提供”推定“不存在”，四类差距使用正确。

制度：每项义务有主体、情形、行为、时限、记录；无“相关部门”；附则完整；涉及职工切身利益的条款已在交付说明中提示民主程序；问责条款与劳动法律和纪检程序衔接。

风险库：字段完整；风险描述含行为、义务和后果；剩余风险评级有理由；责任部门和制度名称与前序成果一致。

职责清单：与合规管理办法职责条款逐项一致。

检查整改意见：每个问题有样本或证据支撑；建议有责任部门和期限；未点名个人，未作违纪违法定性。

验收和年度报告：成效均有事实依据；占位符已逐项列出；报告年度与合同期限的关系已提示。

## 三、扫描命令

在成果文件上运行（`文件` 替换为实际路径）：

```bash
# 占位符残留（客户定稿前应为零，模板类成果除外）
grep -n "【待企业提供\|【待企业确认\|【待律师确定\|××\|XX" 文件

# 范本残留（命中后逐项判断是否与体系设计基准一致）
grep -n "中央企业\|国资委\|首席合规官\|合规委员会\|监事会\|境外" 文件

# 空话和宣传腔
grep -n "进一步加强\|持续完善\|切实提高\|筑牢\|全方位\|深度融合\|赋能\|相关部门\|有关人员\|适时" 文件

# 拉丁字符
grep -nE "[A-Za-z]" 文件
```

命中“中央企业”“国资委”的，判断是否属于正确的依据引用（如“参照《中央企业合规管理办法》”），以及“国资委”是否写明了层级。
